# AGENTS.md

Guidance for agents working in this repository (`stefhol/filer`).

## What this is

`filer` is a Rust CLI that bundles source files and their import/call closure into
chat-ready markdown. Supported languages: `.fe`, Java, Kotlin, Scala, Groovy, C#,
Rust, TS/JS/Vue. It also ships a Neovim plugin in `lua/filer/` and `plugin/`.

## Git workflow (required)

### 1. Update the repo before starting any work

Always start from an up-to-date `master`, never from a stale local branch:

```sh
git checkout master
git pull --ff-only origin master
git fetch --prune origin
```

If the tree is dirty, stop and ask before stashing or discarding anything.

### 2. Issue-based work goes in its own branch

Every issue gets a dedicated branch cut from the freshly updated `master`,
named `<issueNumber>/<slug>`:

```sh
git checkout -b <issueNumber>/<slug> master
git checkout -b 42/call-graph-edges master   # example
```

Look the issue up first (`gh issue view <N>`) and quote its number in the branch
name and the PR body. Use a short kebab-case slug describing the change. One
issue per branch — do not mix unrelated fixes.

Some older branches here still use `issue-<N>-<slug>` (e.g. `issue-8-call-graph`)
or `fix/<slug>`; do not rename or reuse them, only follow the new pattern for new
work.

Commit messages: short imperative subject, optional area prefix, reference the
issue (`CLI: add callers, why, and refs (#9)`). Keep commits reviewable.

### 3. Open a pull request when the work is done

Do not merge into `master` locally. Push the branch and open a PR:

```sh
git push -u origin HEAD
gh pr create --fill --base master
```

PR requirements:

- Body links the issue (`Closes #<N>` when the PR completes it).
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and
  `cargo test --all-targets` pass locally before pushing — CI runs exactly these.
- Behavior changes update `README.md` (commands table, flags, JSON surface).
- New user-visible output or JSON fields respect `schema_version` in
  `src/schema.rs`; bump it for breaking shape changes.
- State/cache writes keep the atomic temp-file + `fsync` + `rename` pattern in
  `src/atomic.rs`.
- Wait for CI to go green; report the PR URL back to the user.

## Build and test

```sh
cargo build --release          # binary at target/release/filer
cargo test --all-targets       # unit + integration tests
cargo clippy --all-targets -- -D warnings
cargo fmt
cd pi-extension && bun install # once; the tools import typebox and pi-tui
cd pi-extension && bun test    # extension tests; spawns target/release/filer
```

Rust 1.89+ and a C compiler (tree-sitter grammars) are required. The `tree-sitter`
CLI must be installed at runtime, not for building. The pi extension needs Bun; run
`cargo build --release` first, because its integration tests spawn
`target/release/filer`; they are skipped when it is missing, which is why the
`extension` CI job builds it first. It also runs `bun install --frozen-lockfile`:
`src/tools.ts` imports `typebox` and `@earendil-works/pi-tui` at runtime, so the
suite fails without the dev dependencies. `pi-extension/bun.lock` is committed.

Integration tests live in `tests/` (`atomic_writes.rs`, `diagnostics.rs`,
`json_surface.rs`) with fixture corpora under `tests/fixtures/`.

## Code map

| Path | Role |
| --- | --- |
| `src/main.rs` | clap CLI, subcommands, output wiring |
| `src/index.rs` | project walk, cached index (root key, mtime + size) |
| `src/resolve.rs` | import resolution, call graph (`Edge`/`Graph`), units |
| `src/lang.rs` | `Language`, `Granularity`, symbol/member kinds |
| `src/<lang>.rs` | per-language tree-sitter extraction (java, kotlin, scala, groovy, csharp, rust, fe, web) |
| `src/bundle.rs` | markdown rendering, scopes, fences |
| `src/state.rs` | `.filer/bundle.toml` branch state |
| `src/atomic.rs` | atomic + locked file writes |
| `src/error.rs` | machine-readable errors, exit codes |
| `src/schema.rs` | JSON `schema_version` |
| `pi-extension/` | pi extension: adapter over the CLI (spawn, discovery, schema guard, operations) |
| `lua/filer/`, `plugin/` | Neovim plugin |

## Conventions

- Errors are structured (`FilerError`) with stable exit codes; never `panic!` or
  `unwrap()` on user input, filesystem or parse results.
- Unresolved imports are reported, not fatal — third-party libs are expected to
  be unresolved.
- Keep the JSON surface (`--json`) and the human output in sync.
- Prefer extending an existing language module over adding special cases in
  `resolve.rs`.
- Formatting: `cargo fmt` defaults, no clippy allowances without a comment.
- New source files need tests that would fail without the change.

## Releases

Do not bump versions or tag manually. Releases run through
Actions → *Cut release* (`.github/workflows/cut-release.yml`); packaging is
generated by cargo-dist from `dist-workspace.toml` (refresh with
`dist generate`).
